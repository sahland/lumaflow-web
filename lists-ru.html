Руководство / Списки

Данных может быть много. Смонтированных строк — нет.

ListView<T> использует нативную виртуализацию UI Toolkit и монтирует Widget только для видимых и подготовленных к переиспользованию строк.

Используйте для

Растущих коллекцийПроектов, сообщений, результатов поиска и других прокручиваемых данных.

Список из 2000 проектов: поиск, сортировка и выбор.

После первого урока добавьте файл ниже и using LumaFlowDocs.NextSteps; в AppRoot. Замените CounterPage на new ProjectListDemo() внутри существующего Scaffold. Bootstrap, тема и Mount остаются прежними.

Пример полностью локальный: он создаёт 2000 тестовых проектов в памяти, не загружает их с сервера и не записывает изменения на диск. Идентификатор проекта не меняется при сортировке и не переиспользуется после удаления.

ProjectListDemo.cs · полный файл
using System;
using System.Collections.Generic;
using System.Linq;
using LumaFlow;

namespace LumaFlowDocs.NextSteps {
    public sealed class ProjectListDemo : StatefulWidget<ProjectListDemoState> { }

    public sealed class ProjectListDemoState : WidgetState {
        private readonly List<Project> _all = new();
        private readonly State<string> _query = new("");
        private readonly State<IReadOnlyList<Project>> _visible = new(Array.Empty<Project>());
        private readonly State<IReadOnlyList<WidgetKey>> _selected = new(Array.Empty<WidgetKey>());
        private readonly State<string> _order = new("Ascending");
        private readonly ListViewController _scroll = new();
        private bool _descending;
        private int _nextId = 2001;

        protected override void InitState() {
            for (var id = 1; id <= 2000; id++) _all.Add(new Project(id));
            Refresh();
        }

        public override Widget Build(BuildContext context) => SizedBox.Expand(new Padding(
            new Column(new Widget[] {
                new Text("Projects", context.Theme!.Typography.Title),
                new TextField(_query, label: "Search", onChanged: _ => Refresh()),
                new Row(new Widget[] {
                    new Button("Reverse order", ReverseOrder),
                    new Button("Clear search", ClearSearch)
                }, gap: 8f),
                new Row(new Widget[] {
                    new Button("Add project", AddProject),
                    new Button("Delete selected", DeleteSelected)
                }, gap: 8f),
                new ReactiveBuilder<string>(_order, value => new Text(value)),
                new ReactiveBuilder<IReadOnlyList<Project>>(_visible, rows => new Text(
                    rows.Count == 0 ? "No matches. Clear the search." : $"Matches: {rows.Count}")),
                new ReactiveBuilder<IReadOnlyList<WidgetKey>>(_selected, keys => new Text(
                    keys.Count == 0 ? "Selected: none" : $"Selected: {keys[0].Value}")),
                new Expanded(new ListView<Project>(_visible,
                    project => new Padding(new Text(project.Name), EdgeInsets.All(8f)),
                    itemHeight: 44f,
                    itemKey: KeyOf,
                    selectionMode: ListSelectionMode.Single,
                    selectedKeys: _selected,
                    controller: _scroll))
            }, gap: 12f), EdgeInsets.All(24f)));

        private void Refresh() {
            var term = _query.Value.Trim();
            var matches = _all.Where(p => p.Name.IndexOf(term, StringComparison.OrdinalIgnoreCase) >= 0);
            _visible.Value = (_descending ? matches.OrderByDescending(p => p.Id) : matches.OrderBy(p => p.Id)).ToArray();
            _scroll.JumpTo(0f);
        }

        private void ReverseOrder() {
            _descending = !_descending;
            _order.Value = _descending ? "Descending" : "Ascending";
            Refresh();
        }

        private void ClearSearch() {
            _query.Value = "";
            Refresh(); // Programmatic assignment does not replay TextField.onChanged.
        }

        private void AddProject() {
            _all.Add(new Project(_nextId++));
            Refresh();
        }

        private void DeleteSelected() {
            var keys = new HashSet<WidgetKey>(_selected.Value);
            _all.RemoveAll(p => keys.Contains(KeyOf(p)));
            _selected.Value = Array.Empty<WidgetKey>();
            Refresh();
        }

        private static WidgetKey KeyOf(Project project) => new($"project:{project.Id}");

        private sealed class Project {
            public Project(int id) { Id = id; Name = $"Project {id:D4}"; }
            public int Id { get; }
            public string Name { get; }
        }
    }
}

Что проверить руками

  1. Сначала видны Matches: 2000 и первые проекты. Прокрутите вниз: список не должен увеличивать высоту всей страницы.
  2. Нажмите строку Project 0001. Над списком появится Selected: project:1.
  3. Нажмите Reverse order: порядок изменится, но выбранным останется тот же ID, не строка на прежнем индексе.
  4. Введите в Search «2000» — останется один результат. Введите «zzz» — появится подсказка No matches. Clear the search.
  5. Нажмите Clear search: вернутся все строки. Программное изменение _query не запускает onChanged, поэтому этот обработчик сам вызывает Refresh.
  6. При пустом поиске нажмите Add project: появится Matches: 2001. Выберите строку и нажмите Delete selected — удалится именно выбранный проект, а выбор очистится.

Данные, представление и выбор — три разные вещи

Владельцы данных списка
ПолеЗачем оно
_allПолный набор моделей. Это обычный List, не реактивная коллекция.
_visibleНовый снимок отфильтрованных и отсортированных моделей, который наблюдает ListView.
_selectedID выбранной модели в виде WidgetKey, не индекс и не ссылка на нативную строку.
_scrollДолгоживущий контроллер прокрутки одного списка.

Refresh создаёт новый массив через ToArray и присваивает его в State. Одного _all.Add(...) недостаточно: State не замечает внутреннюю мутацию обычного списка. Не пытайтесь «починить» это повторным Mount или передачей прежнего экземпляра коллекции в State.

Что реально экономит виртуализация

ListView не создаёт 2000 смонтированных строк сразу: UI Toolkit переиспользует видимые строки и небольшой запас. Но все 2000 моделей и снимок всё ещё находятся в памяти, поиск и сортировка всё ещё обрабатывают данные. Это не серверная пагинация и не обещание постоянной стоимости обновления.

В примере фиксированная высота строки 44 UI-единицы. Внутри — короткий однострочный текст с отступом 8. Если добавите длинное описание, крупный масштаб текста или многострочную карточку, уберите itemHeight и используйте dynamic-height режим. Нельзя обещать строке 44, а рисовать внутри карточку высотой 100.

Key — идентичность, не хранилище.

itemKey связывает модель и реализованную строку при обновлении. Ключ должен быть уникальным и стабильным: ID подходит, индекс, имя проекта и новый Guid на каждый Build — нет. Но строку могут убрать при виртуализации; важный черновик, флажок или прогресс храните вне строки по ID, а не рассчитывайте только на WidgetState.

Почему выбор остаётся, хотя строка скрылась поиском

В этом примере фильтр намеренно не очищает _selected: выбранный ID может временно не присутствовать в результатах. После Clear search выбор снова станет виден. Delete selected удаляет выбранную модель даже если фильтр её скрывает. Это политика приложения; если нужно выбирать только среди результатов, явно очищайте отсутствующие ключи при Refresh.

Прокрутка и ограниченная высота

ListView уже содержит свою прокрутку. Не помещайте его в дополнительный вертикальный ScrollView. Здесь Scaffold даёт высоту экрану, SizedBox.Expand заполняет область, Column оставляет место заголовкам, Expanded отдаёт остаток списку. Подробный разбор размеров и Expanded.

Refresh намеренно возвращает прокрутку к началу через JumpTo(0). Если продукт должен сохранять позицию, уберите этот сброс и продумайте поведение при изменении фильтра. Для перехода к конкретному проекту используйте ScrollTo с его ключом: метод вернёт false, если ключ отсутствует в текущих результатах или controller не подключён.

Частые ошибки

  • Обновили List, но экран не изменился: нужен новый снимок в State.
  • После сортировки выбран другой проект: храните ID/ключ, не selectedIndex.
  • Список пустой или высотой в одну строку: проверьте конечную высоту viewport и Expanded, не увеличивайте itemHeight вслепую.
  • После скролла пропадает ввод в строке: перенесите важные данные в владельца по ID.
  • Поиск тормозит на больших данных: виртуализация не ускоряет фильтрацию. Для большого каталога добавьте задержку ввода, индексацию или серверный поиск, а устаревшие ответы отменяйте.

Builder строки вызывается повторно при переиспользовании. Он должен создавать описание UI; не запускайте в нём загрузку с сервера, воспроизведение звука или создание долгоживущих контроллеров.

Следующий шаг: открывать детали выбранного проекта и возвращаться назад.

Выше — полный запускаемый пример. Далее — справочные фрагменты API; ProjectRow и другие имена экранов/моделей обозначают ваш код, не встроенные классы пакета.

Column для малого набора. ListView для растущего.

Column + ScrollView

Маленький статичный список

Все дети монтируются сразу. Подходит для настроек или нескольких карточек.

ListView<T>

Большая коллекция

Монтируются только нужные строки; переиспользование выполняет нативный ListView.

Начните с типизированного builder строки.

Для строк одинаковой высоты укажите itemHeight. Если высота зависит от содержимого, не передавайте её — будет использована dynamic-height виртуализация.

ProjectsList.cs
new ListView<Project>(
  projects,
  project => new ProjectRow(project),
  itemHeight: 56f);

Добавляйте Key строкам с состоянием.

У каждой модели должен быть уникальный стабильный ключ. При вставке и сортировке он связывает совместимую реализованную строку с тем же объектом данных. Это не гарантирует сохранение WidgetState после удаления строки виртуализацией; важные значения храните у внешнего владельца по ID.

ProjectsList.cs
new ListView<Project>(
  projects,
  project => new ProjectRow(project),
  itemHeight: 56f,
  itemKey: project => new WidgetKey(project.Id));
Не используйте индекс как Key.

После вставки индекс станет принадлежать другому объекту. Берите идентификатор из данных: project.Id, message.Id и аналогичный.

Не изменяйте реактивную коллекцию на месте.

Храните State<IReadOnlyList<T>> и присваивайте новое значение целиком. Мутация обычного List сама по себе не отправит уведомление.

Список отображает выбор, но не владеет им.

Выбранные элементы хранятся как ключи во внешнем State. Пользовательский ввод сначала обновляет State, затем вызывает callback.

ProjectsList.cs
var selected = new State<IReadOnlyList<WidgetKey>>(
  Array.Empty<WidgetKey>());

new ListView<Project>(
  projects, BuildRow,
  itemKey: project => new WidgetKey(project.Id),
  selectionMode: ListSelectionMode.Multiple,
  selectedKeys: selected);

Сохраните controller, если позиция имеет значение.

ListViewController должен жить там же, где конфигурация списка, а не создаваться в Build.

ProjectsList.cs
private readonly ListViewController _controller = new();

_controller.JumpTo(320f);
_controller.ScrollTo(new WidgetKey(projectId));
