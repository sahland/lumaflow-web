Руководство / Контролы и формы

Значение принадлежит приложению, а не полю ввода.

Контролы LumaFlow управляются явным State. UI Toolkit сохраняет нативный фокус и клавиатурное поведение, а приложение остаётся единственным источником данных.

Полная форма: ввод → проверка → сохранение → отмена.

Возьмите AppRoot и тему из первого урока. Создайте ProjectFormDemo.cs ниже, добавьте using LumaFlowDocs.NextSteps; в AppRoot и замените CounterPage на new ProjectFormDemo() внутри существующего Scaffold. Bootstrap не меняйте; компонент на GameObject добавлять не нужно.

«Save locally» здесь сохраняет только в памяти экрана.

Пример не пишет файл, не отправляет запросы и не рассылает email. Checkbox — учебное значение настройки. Закрытие приложения или удаление этой ветки уничтожит сохранённые значения. Настоящее хранилище подключают отдельно.

ProjectFormDemo.cs · полный файл
#nullable enable
using LumaFlow;

namespace LumaFlowDocs.NextSteps {
    public sealed class ProjectFormDemo : StatefulWidget<ProjectFormDemoState> { }

    public sealed class ProjectFormDemoState : WidgetState {
        private readonly State<string> _name = new("");
        private readonly State<bool> _updates = new(false);
        private readonly State<string> _status = new("Not saved");
        private readonly State<int> _userChanges = new(0);
        private readonly FormState _form = new(FormValidationMode.OnSubmit);
        private FormField<string> _nameField = null!;
        private string _savedName = "";
        private bool _savedUpdates;

        protected override void InitState() {
            _nameField = new FormField<string>(_name, value =>
                value.Trim().Length >= 3 ? null : "Use at least 3 characters.");
        }

        public override Widget Build(BuildContext context) => new ScrollView(new Center(
            ConstrainedBox.AtMost(new Padding(
                new Form(_form, new Column(new Widget[] {
                    new Text("Project settings", context.Theme!.Typography.Title),
                    new TextField(_nameField, label: "Project name",
                        placeholder: "Enter a name", onChanged: _ => UserEdited()),
                    new Checkbox(_updates, label: "Email updates",
                        onChanged: _ => UserEdited()),
                    new Button("Save locally", () => { _form.Submit(SaveValidated); }),
                    new Button("Load example", LoadExample),
                    new Button("Restore saved", RestoreSaved),
                    new ReactiveBuilder<string>(_status, value => new Text(value)),
                    new ReactiveBuilder<int>(_userChanges,
                        value => new Text($"User changes: {value}"))
                }, gap: 16f), onSubmit: SaveValidated),
                EdgeInsets.All(24f)), width: 520f)));

        private void UserEdited() {
            _userChanges.Value++;
            _status.Value = "Unsaved changes";
        }

        // Form.Submit invokes this only after mounted fields pass validation.
        private void SaveValidated() {
            _savedName = _name.Value.Trim();
            _savedUpdates = _updates.Value;
            _status.Value = $"Saved locally: {_savedName}";
        }

        private void LoadExample() {
            _name.Value = "Demo project";
            _updates.Value = true;
            _form.ClearValidation();
            _status.Value = "Example loaded (not saved)";
        }

        private void RestoreSaved() {
            _name.Value = _savedName;
            _updates.Value = _savedUpdates;
            _form.ClearValidation();
            _status.Value = "Restored last saved values";
        }
    }
}

Проверьте сценарий по шагам

  1. Сразу нажмите Save locally. Появится ошибка Use at least 3 characters.; фокус перейдёт к имени. Некорректные данные не сохраняются.
  2. Введите «Мой проект» и включите Email updates. Счётчик User changes растёт от действий пользователя. Нажмите Save locally — увидите Saved locally: Мой проект.
  3. Нажмите Load example: поле станет Demo project, checkbox включится, статус сообщит, что пример ещё не сохранён. User changes не увеличится: значения записаны из кода.
  4. Нажмите Restore saved: вернутся имя и checkbox последнего успешного сохранения, не Demo project. До первого сохранения восстановятся пустое имя и выключенный checkbox.
  5. Введите новое корректное имя и нажмите Enter в однострочном поле. Форма выполнит то же сохранение. Для многострочного TextField Enter означает новую строку, а не submit.

Зачем три разных объекта

Значение, поле и форма
ОбъектЗа что отвечает
State<string> _nameТекущий черновик. Его читает и изменяет TextField.
FormField<string> _nameFieldСсылка на тот же State, функция проверки и ErrorText. Это не вторая копия имени.
FormState _form + FormПроверка всех зарегистрированных полей в этой ветке, submit и фокус на первой ошибке.

FormField связывается с Form через смонтированный TextField: одного создания объектов недостаточно. Поле должно находиться внутри Form. Валидатор возвращает строку ошибки или null, если всё хорошо; не выполняйте в нём сеть и не изменяйте другие значения.

Почему кнопка и Enter вызывают разные методы

Обычная кнопка вызывает _form.Submit(SaveValidated): сначала проверка, затем действие. В Form(..., onSubmit: SaveValidated) сама Form уже проводит проверку при Enter. Поэтому SaveValidated не проверяет форму повторно и не вызывается из Build.

OnSubmit показывает ошибки после попытки сохранения. Если нужно проверять сразу при изменении значения, выберите FormValidationMode.OnChange. FormState.IsValid отслеживает валидность и до submit, но её наличие не означает, что сообщения уже показаны.

Пользовательский callback и программное изменение

TextField/Checkbox сначала обновляют State, потом вызывают onChanged. Запись _name.Value = "Demo project" обновляет видимое поле без повторного onChanged. Поэтому Load example и Restore saved явно задают статус сами. Если действие должно выполняться при любом изменении State, используйте Subscribe у владельца и освободите подписку в Dispose; не превращайте onChanged в универсальный обработчик загрузки.

Что означает «сбросить форму»

ClearValidation убирает сообщения, но не меняет данные и не делает пустое имя корректным. RestoreSaved сначала возвращает оба значения, затем очищает ошибки. Сохранённая копия _savedName/_savedUpdates здесь намеренная: это последняя подтверждённая версия, а не конкурирующий источник текущего ввода.

Частые ошибки

Создание FormField в Build теряет стабильного владельца и ошибки. Submit без Form или с полями вне её области не проверит отсутствующие поля. Rebuild не является сбросом данных. Сохранение в onChanged запускается при каждом пользовательском изменении, а не только по кнопке Save.

Если сохранение станет сетевым

Этот пример синхронный. Для сети добавьте состояние «сохраняется», запрет повторной отправки, обработку ошибки и отмену операции при уходе с экрана. Не показывайте «сохранено» до ответа сервера. Результат фоновой операции применяйте в Unity-потоке и не обновляйте уже удалённую ветку. Сервисы сети лучше передавать через зависимости, а не создавать в Build.

Выше — полный запускаемый пример. Далее — справочные фрагменты отдельных API; их нельзя копировать как готовые файлы.

Один State — один источник истины.

Поле отображает текущее значение State. Ввод пользователя обновляет State. Изменение State из кода обновляет поле без имитации пользовательского события.

ProjectForm.cs
private readonly State<string> _name = new("");

new TextField(
  _name,
  label: "Название проекта",
  placeholder: "Введите название",
  onChanged: value => SaveDraft(value));

Программное обновление не вызывает onChanged повторно.

Это предотвращает цикл «State изменил control → control снова записал State». Callback обозначает действие пользователя, а не любое визуальное обновление.

Не храните вторую копию значения.

Если одновременно поддерживать поле класса и State, они разойдутся. Domain model можно обновлять в callback, но отображаемое значение должно иметь одного владельца.

Валидация тоже является состоянием.

FormState координирует поля, а FormField<T> хранит значение и результат проверки. При submit сначала проверьте форму и только потом отправляйте данные.

Не перестраивайте дерево ради сброса формы.

Сбросьте значения и ошибки через владельца формы. Rebuild описывает интерфейс заново, но не решает, какие данные продукта удалить.

Используйте нативное клавиатурное поведение.

Встроенные контролы уже участвуют в focus ring UI Toolkit. Не заменяйте их визуальным Container с callback, если элемент должен работать с Tab, Enter или экранным диктором.

Для программного перехода храните FocusNode у владельца экрана. Не создавайте его внутри Build.
