Руководство / Навигация

Маршруты и временный UI должны иметь явного владельца.

Navigator хранит историю экранов. OverlayController управляет диалогами, drawer, popover и toast поверх содержимого.

Главное правило

Создавайте controller вне BuildОдин controller подключается к одному соответствующему host.

В руководстве

Два экрана: полный примерNavigator или OverlayСоздание hostPush и ReplaceМодальный диалогBack и EscapeЖизненный цикл

Рабочий маршрут: список → детали → назад.

Добавьте LocalCounter.cs из урока о локальном состоянии и файл ниже. В AppRoot импортируйте LumaFlowDocs.NextSteps и замените CounterPage на new NavigationDemo() внутри Scaffold. Bootstrap, Theme и Mount не меняются.

NavigationDemo.cs · полный файл
#nullable enable
using System;
using LumaFlow;

namespace LumaFlowDocs.NextSteps {
    public sealed class NavigationDemo : StatefulWidget<NavigationDemoState> { }

    public sealed class NavigationDemoState : WidgetState {
        private Navigator _navigator = null!;
        private readonly OverlayController _overlay = new();

        protected override void InitState() {
            _navigator = new Navigator(new HomePage(OpenDetails));
        }

        private void OpenDetails() => _navigator.Push(new Route(
            new WidgetKey("project-1"),
            new DetailsPage(() => { _navigator.Pop(); }),
            RouteTransition.Fade(TimeSpan.FromMilliseconds(180))));

        public override Widget Build(BuildContext context) => new BackNavigation(
            new OverlayHost(new NavigatorHost(_navigator), _overlay),
            _navigator, _overlay);

        private sealed class HomePage : StatelessWidget {
            private readonly Action _open;
            public HomePage(Action open) => _open = open;
            public override Widget Build(BuildContext context) => new Padding(
                new Column(new Widget[] {
                    new Text("Project list"),
                    new LocalCounter(),
                    new Button("Open project 1", _open)
                }, gap: 16f), EdgeInsets.All(24f));
        }

        private sealed class DetailsPage : StatelessWidget {
            private readonly Action _back;
            public DetailsPage(Action back) => _back = back;
            public override Widget Build(BuildContext context) => new Padding(
                new Column(new Widget[] {
                    new Text("Project 1 details"),
                    new Button("Back to projects", _back)
                }, gap: 16f), EdgeInsets.All(24f));
        }
    }
}

Что проверить

  1. На Project list трижды нажмите Increment local count.
  2. Нажмите Open project 1 — появится Project 1 details.
  3. Нажмите Back to projects — вернётся список с Local count: 3.
  4. Повторите переход: в истории должны быть список и текущие детали, не копии главной страницы.

Почему число сохранилось: Push оставляет предыдущий маршрут смонтированным, но неактивным. Pop удаляет детали и возвращает прежний экран. Replace не сохраняет удалённую ветку и её WidgetState.

Зачем InitState: Navigator создаётся один раз для смонтированного NavigationDemo. Создание в Build сбрасывало бы историю при перестроениях. WidgetState владеет контроллерами; hosts подключаются к ним и освобождают своё дерево при unmount. Сам Navigator не имеет Dispose.

Зачем пустой OverlayController: диалогов пока нет, но BackNavigation принимает оба контроллера и сначала проверяет верхний overlay. Поэтому показаны согласованные NavigatorHost, OverlayHost и BackNavigation. Явная кнопка назад работает через Pop; автоматический Escape требует фокуса внутри этого UI.

Push — не переключатель вкладок меню.

Push при каждом тапе бесконтрольно увеличивает историю. Для разделов без истории можно хранить выбранный раздел в State, для замены маршрута — использовать Replace.

project-1 — ключ конкретного маршрута, уникальный среди одновременно открытых маршрутов. Повторный Push того же ключа без Pop недопустим. NavigationSnapshot хранит историю в памяти, не восстанавливает её автоматически после закрытия APK.

Полный пример — выше; далее справочные фрагменты. Короткие блоки ниже показывают отдельные API и не являются готовыми файлами. Имена вроде DashboardPage, ProjectDetails или Location обозначают ваши экраны и модели, а не встроенные типы LumaFlow.

Переход между экранами и временный слой — разные задачи.

Navigator

Экран приложения

Маршрут участвует в истории. Back возвращает предыдущий экран вместе с его локальным состоянием.

OverlayController

Временный интерфейс

Диалог, меню, toast или drawer показываются над текущим маршрутом и закрываются независимо.

Создайте области один раз.

Controller хранит изменяемый стек, поэтому он должен принадлежать приложению или StatefulWidget. Host только отображает состояние своего controller.

ApplicationFlow.cs
private readonly Navigator _navigator =
  new(new DashboardPage());
private readonly OverlayController _overlay = new();

new BackNavigation(
  new OverlayHost(
    new NavigatorHost(_navigator), _overlay),
  _navigator, _overlay);
Не создавайте controller в Build.

Повторный Build создаст пустой стек и потеряет прежнюю историю. Controller должен переживать перестроения описания.

Push сохраняет историю. Replace заменяет текущую вершину.

Используйте Push, когда пользователь должен вернуться назад. Используйте Replace после входа, onboarding или другого шага, возврат к которому не имеет смысла.

ApplicationFlow.cs
_navigator.Push(new Route(
  new WidgetKey($"project:{project.Id}"),
  new ProjectDetails(project),
  RouteTransition.Fade(
    TimeSpan.FromMilliseconds(180))));

Key маршрута нужен, когда его идентичность важна для восстановления или поиска в стеке. Он должен описывать конкретный логический экран.

Верхний modal получает ввод вместо содержимого под ним.

Если пользователь обязан принять решение, запретите закрытие кликом по barrier и кнопкой Back. Закройте modal через возвращённый handle или действие внутри диалога.

DeleteProject.cs
_overlay.ShowModal(
  new Dialog(
    new Text("Удалить проект?")),
  new ModalOptions(
    dismissOnBarrier: false,
    dismissOnBack: false));

Back закрывает верхнюю область первой.

BackNavigation обрабатывает действие в порядке: верхний overlay, активный route, затем ничего на корневом экране. Поэтому Escape не проходит сквозь открытый диалог к маршруту под ним.

Храните только ту историю, которая нужна пользователю.

Неактивные маршруты остаются смонтированными, чтобы сохранить локальное состояние. Это полезно, но бесконечный стек удерживает деревья и данные.

Ограничивайте историю намеренно.

Используйте Replace, PopToRoot или ClearAndPush в потоках, которым не нужен полный back stack.
