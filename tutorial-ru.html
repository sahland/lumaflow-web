Что мы соберём и сколько файлов действительно нужно

Сделаем приложение «Счётчик проектов»: заголовок, число и кнопку «Добавить проект». Нажатие меняет число без ручного поиска UI-элементов. Сначала всё будет в одном файле. Затем мы разложим тот же экран на пять файлов, добавим общую тему и разберём обязанности каждого класса.

AppBootstrap, AppDependencies, AppRoot и AppTheme — не обязательные типы LumaFlow.

Это имена классов нашего приложения. Вы создаёте их сами; можно назвать их иначе или не выделять в отдельные файлы. Для первого экрана достаточно одного MonoBehaviour. Не нужно копировать архитектуру большого проекта, чтобы вывести текст.

Понадобятся Unity 6+, базовое понимание классов C# и Git для установки из Git URL. Примеры рассчитаны на API LumaFlow 0.1.1; версию смотрите в Package Manager. Все файлы приведены полностью: многоточий и скрытых сервисов нет.

1. Установите LumaFlow

  1. Откройте Window → Package Management → Package Manager (в некоторых версиях Unity — Window → Package Manager).
  2. Нажмите + → Install package from git URL / Add package from git URL.
  3. Вставьте https://github.com/sahland/lumaflow.git и подтвердите установку.
  4. Дождитесь импорта. Убедитесь, что в Console нет красных ошибок, а пакет LumaFlow виден в списке.

UPM-пакет называется com.sahland.lumaflow, а пространство имён C# — LumaFlow. Это разные вещи. Уже установленный пакет повторно подключать не нужно. Если Unity не находит Git, установите Git и перезапустите Editor. Для команды фиксируйте проверенный tag/commit в Git URL, а не обновляйтесь незаметно вместе с веткой.

Контрольная точка: пакет установлен, компиляция завершилась без ошибок. Пока интерфейса на экране нет — это нормально.

2. Подготовьте место, где Unity покажет интерфейс

  1. Создайте и сохраните пустую сцену. В Hierarchy создайте пустой GameObject с именем App.
  2. Через Add Component добавьте UI Document (UIDocument).
  3. В Project: Create → UI Toolkit → Panel Settings Asset. Назовите asset AppPanelSettings.
  4. Перетащите его в поле Panel Settings у UI Document. Для урока выберите Scale Mode → Constant Pixel Size, Scale = 1. Поле Target Texture оставьте пустым: выводим в Game, не в RenderTexture.
  5. В Panel Settings проверьте Theme Style Sheet: назначьте стандартную runtime-тему Unity, если Unity не назначила её сама. Для теста оставьте стандартные настройки шрифтов.
  6. Поле Source Asset у UI Document оставьте пустым. UXML для runtime-урока не нужен.

UIDocument — компонент-мост к UI Toolkit. Panel Settings — настройки вывода и масштабирования, а не тема приложения LumaFlow. rootVisualElement — корневой контейнер, в который мы поместим дерево. Обычный uGUI Canvas для этого не требуется.

Контрольная точка: у App есть UI Document с назначенным Panel Settings. Game ещё может быть пустым.

3. Получите рабочее приложение в одном файле

Создайте Assets/FirstApp/FirstScreen.cs и вставьте весь код ниже. Дождитесь компиляции, затем добавьте компонент First Screen на App. Имя файла должно совпадать с именем MonoBehaviour-класса. Нажмите Play и откройте Game.

FirstScreen.cs · полный файл
#nullable enable
using System.Collections;
using LumaFlow;
using UnityEngine;
using UIDocument = UnityEngine.UIElements.UIDocument;
using Framework = LumaFlow.LumaFlow;

namespace LumaFlowDocs.Minimal {
    [RequireComponent(typeof(UIDocument))]
    [DisallowMultipleComponent]
    public sealed class FirstScreen : MonoBehaviour {
        private readonly State<int> _count = new(0);
        private MountHandle? _mount;
        private Coroutine? _startup;

        private void OnEnable() => _startup = StartCoroutine(MountWhenReady());

        private IEnumerator MountWhenReady() {
            yield return null;
            var document = GetComponent<UIDocument>();
            if (document.panelSettings == null) {
                Debug.LogError("Assign Panel Settings on the UIDocument.", this);
                _startup = null;
                yield break;
            }
            while (document.rootVisualElement?.panel == null) yield return null;
            _mount = Framework.Mount(BuildScreen(), document.rootVisualElement);
            _startup = null;
        }

        private Widget BuildScreen() => new Scaffold(new Center(new Padding(
            new Column(new Widget[] {
                new Text("My first LumaFlow app"),
                new ReactiveBuilder<int>(_count,
                    value => new Text($"Projects: {value}")),
                new Button("Add project", () => _count.Value++)
            }, gap: 12f), EdgeInsets.All(24f))));

        private void OnDisable() {
            if (_startup != null) StopCoroutine(_startup);
            _startup = null;
            _mount?.Dispose();
            _mount = null;
        }
    }
}

Скачать FirstScreen.cs

Ожидаемый результат: заголовок, Projects: 0 и кнопка Add project. После трёх нажатий — Projects: 3. Пока оформление базовое: собственную тему добавим ниже.

MountWhenReady — короткая coroutine запуска: yield return null отдаёт Unity один кадр, а цикл ждёт подключения UIDocument к панели. Это защищает от слишком раннего mount на устройствах. После запуска coroutine завершается; постоянного Update здесь нет. Если UI Document выключен, включите его вместе с App.

Framework — псевдоним для LumaFlow.LumaFlow, чтобы не путать класс с пространством имён. Псевдоним UIDocument импортирует только нужный Unity-тип: общий using UnityEngine.UIElements; вместе с using LumaFlow; делает имя Button неоднозначным.

4. Разберите один клик, а не весь фреймворк сразу

  1. new Button(..., () => _count.Value++) задаёт действие на нажатие. Запись () => означает «выполнить эту функцию позже», не во время Build.
  2. State<int> хранит целое число и сообщает подписчикам о его изменении. Это не обычная локальная переменная.
  3. ReactiveBuilder<int> получает State и функцию, создающую текст из текущего числа. После изменения LumaFlow обновляет эту ветку.
  4. Column раскладывает детей вертикально, gap задаёт расстояние между ними, Padding — внутренний отступ, Center — центрирование, Scaffold — основную область экрана.

Widget — описание желаемого интерфейса, а не GameObject. Build() создаёт такое описание; LumaFlow сопоставляет его со смонтированным деревом, а UI Toolkit рисует. Не вызывайте Mount в обработчике каждого клика и не пишите сетевые запросы или PlayOneShot внутри Build.

Состояние создаётся один раз у владельца.

В примере _count — поле компонента, не переменная внутри BuildScreen. Повторный Build не сбрасывает число. У State<T> нет Dispose; подписки ReactiveBuilder освобождаются при удалении его ветки. Если вы вызвали Subscribe вручную — освободите полученную подписку сами.

MountHandle — объект управления уже показанным деревом. Dispose() убирает его UI и подписки. Поэтому OnEnable запускает интерфейс, а OnDisable останавливает coroutine и освобождает mount. Сохранение данных на диск здесь не реализовано: перезапуск Play Mode может сбросить число.

Коротко о синтаксисе C# в примерах: namespace группирует классы и предотвращает конфликты имён; readonly запрещает заменить ссылку после инициализации; static означает общие данные класса, а не отдельного экрана. #nullable enable включает проверки null: знак ? допускает null, ?. вызывает метод только при наличии объекта, а ! сообщает компилятору, что в этом месте объект уже гарантированно есть. Сам ! ничего не проверяет в runtime.

5. Когда приложение растёт: кто за что отвечает

Однофайловый экран уже работает. Разделение ниже нужно не Unity, а людям: чтобы не смешивать запуск, данные, внешний вид и вёрстку. Не ставьте все эти классы компонентами на GameObject. Компонентом будет только AppBootstrap.

Классы нашего приложения — не классы пакета
КлассПростыми словамиКто создаёт / что менять здесь
AppBootstrapВключатель приложения на сцене: дождаться панели, собрать приложение, вызвать Mount, затем Dispose.Unity вызывает OnEnable/OnDisable. Здесь меняют запуск и время жизни, не вёрстку кнопок.
AppDependenciesОбщие объекты, которые нужны экрану. В уроке — только счётчик и действие добавления.Создаёт Bootstrap один раз за активацию. Позже здесь могут быть сервисы сохранения или сети, но сейчас их нет.
AppRootСамый верхний Widget: объединяет тему и первый экран.Создаёт Bootstrap и передаёт в Mount. Здесь выбирают общие обёртки/стартовую страницу.
AppThemeОбщий набор цветов, размеров текста и стилей контролов.Статические данные создаются один раз. Здесь меняют общий стиль, не бизнес-логику.
CounterPageВёрстка одного экрана и связь кнопки с действием.Создаёт AppRoot. Здесь добавляют текст, отступы, кнопки и реактивные участки.
Unity → AppBootstrap → AppDependencies
                    → Mount(AppRoot, UIDocument.rootVisualElement)
                              → Theme → Scaffold → CounterPage

AppRoot — Widget, не UI Toolkit rootVisualElement. AppTheme — настройки LumaFlow, не Panel Settings и не Unity Theme Style Sheet. AppDependencies — обычный C#-объект, не обязательный DI-контейнер. Названия Controller, Presenter, AppShell тоже являются архитектурными соглашениями, а не магическими требованиями.

6. Разделите тот же пример на файлы

Выйдите из Play Mode. Удалите компонент First Screen с App: иначе два компонента смонтируют два приложения в один документ. Сам файл можете оставить. Создайте папку Assets/FirstApp/Structured, добавьте пять файлов ниже и дождитесь компиляции. Их общий namespace LumaFlowDocs.Structured отделяет урок от ваших существующих AppRoot/AppTheme.

Assets/FirstApp/Structured/
  AppBootstrap.cs     ← единственный MonoBehaviour
  AppDependencies.cs  ← данные и действия
  AppRoot.cs          ← корневая композиция
  AppTheme.cs         ← оформление
  CounterPage.cs      ← вёрстка экрана

AppDependencies.cs — сначала дайте данным владельца

Счётчик живёт вне Build, а AddProject изменяет его значение. Передача объекта через конструктор позволяет экрану использовать тот же счётчик, не создавая новый. Для такого маленького приложения зависимости можно передать прямо в CounterPage; отдельный класс здесь показывает путь роста.

AppDependencies.cs · полный файл
using LumaFlow;

namespace LumaFlowDocs.Structured {
    public sealed class AppDependencies {
        public State<int> ProjectCount { get; } = new(0);

        public void AddProject() => ProjectCount.Value++;
    }
}

AppTheme.cs — один источник общего оформления

ThemeData объединяет палитру, типографику, интервалы, скругления и стили кнопок. Например, OnPrimary — цвет текста на основной кнопке, Canvas — фон Scaffold. Создание темы не выводит её на экран: ниже AppRoot применит её через Theme. Явно заданный стиль конкретного виджета может перекрывать значения темы.

AppTheme.cs · полный файл
using LumaFlow;
using UnityEngine;

namespace LumaFlowDocs.Structured {
    public static class AppTheme {
        private static readonly Color Ink = new Color32(44, 48, 62, 255);
        private static readonly Color Paper = new Color32(245, 244, 240, 255);
        private static readonly Color Accent = new Color32(98, 83, 150, 255);

        public static ThemeData Data { get; } = new(
            colors: new ColorScheme(
                canvas: Paper, surface: Color.white, surfaceVariant: Paper,
                primary: Accent, primaryContainer: Paper, onPrimary: Color.white,
                onSurface: Ink, onSurfaceVariant: Color.gray, outline: Color.gray),
            typography: new TypographyTheme(
                title: new TextStyle(Ink, 26f, FontStyle.Bold),
                headline: new TextStyle(Ink, 20f, FontStyle.Bold),
                body: new TextStyle(Ink, 16f),
                label: new TextStyle(Color.white, 16f)),
            spacing: new SpacingTheme(4f, 8f, 12f, 20f, 32f),
            radius: new RadiusTheme(
                BorderRadius.All(8f), BorderRadius.All(12f), BorderRadius.All(20f)),
            buttonTheme: new ButtonTheme(
                primary: new ButtonStyle(background: Accent, foreground: Color.white,
                    padding: EdgeInsets.Symmetric(horizontal: 20f, vertical: 12f),
                    shape: BorderRadius.All(12f), minimumSize: new Vector2(120f, 48f)),
                secondary: new ButtonStyle(background: Paper, foreground: Ink,
                    padding: EdgeInsets.All(12f), shape: BorderRadius.All(12f))));
    }
}

CounterPage.cs — опишите экран

StatelessWidget означает, что этот Widget сам не владеет изменяемым локальным UI-состоянием. Это не значит, что экран статичен: ReactiveBuilder обновляет число из переданного State. BuildContext содержит настройки текущей ветки; Theme! безопасен здесь, потому что AppRoot всегда оборачивает страницу в Theme.

CounterPage.cs · полный файл
using LumaFlow;

namespace LumaFlowDocs.Structured {
    public sealed class CounterPage : StatelessWidget {
        private readonly AppDependencies _app;

        public CounterPage(AppDependencies app) => _app = app;

        public override Widget Build(BuildContext context) => new Center(new Padding(
            new Column(new Widget[] {
                new Text("Project counter", context.Theme!.Typography.Title),
                new ReactiveBuilder<int>(_app.ProjectCount,
                    value => new Text($"Projects: {value}")),
                new Button("Add project", _app.AddProject)
            }, gap: 16f), EdgeInsets.All(24f)));
    }
}

AppRoot.cs — соедините тему и страницу

Сначала Theme передаёт настройки потомкам, затем Scaffold создаёт область экрана, потом CounterPage строит контент. Позже здесь удобно разместить навигацию или OverlayHost — для счётчика они не нужны.

AppRoot.cs · полный файл
using LumaFlow;

namespace LumaFlowDocs.Structured {
    public sealed class AppRoot : StatelessWidget {
        private readonly AppDependencies _app;

        public AppRoot(AppDependencies app) => _app = app;

        public override Widget Build(BuildContext context) => new Theme(
            AppTheme.Data,
            new Scaffold(new CounterPage(_app)));
    }
}

AppBootstrap.cs — соедините приложение со сценой

Bootstrap создаёт зависимости и MountHandle. Он не ищет кнопку или текст: вёрсткой управляет дерево виджетов. При выключении сначала удаляется UI, затем отпускается ссылка на зависимости. Здесь только State, поэтому AppDependencies не требует Dispose. Если добавите собственные IDisposable-сервисы, освободите их после mount.

AppBootstrap.cs · полный файл
#nullable enable
using System.Collections;
using LumaFlow;
using UnityEngine;
using UIDocument = UnityEngine.UIElements.UIDocument;
using Framework = LumaFlow.LumaFlow;

namespace LumaFlowDocs.Structured {
    [RequireComponent(typeof(UIDocument))]
    [DisallowMultipleComponent]
    public sealed class AppBootstrap : MonoBehaviour {
        private AppDependencies? _app;
        private MountHandle? _mount;
        private Coroutine? _startup;

        private void OnEnable() {
            _app = new AppDependencies();
            _startup = StartCoroutine(MountWhenReady());
        }

        private IEnumerator MountWhenReady() {
            yield return null;
            var document = GetComponent<UIDocument>();
            if (document.panelSettings == null) {
                Debug.LogError("Assign Panel Settings on the UIDocument.", this);
                _startup = null;
                yield break;
            }
            while (document.rootVisualElement?.panel == null) yield return null;
            _mount = Framework.Mount(new AppRoot(_app!), document.rootVisualElement);
            _startup = null;
        }

        private void OnDisable() {
            if (_startup != null) StopCoroutine(_startup);
            _startup = null;
            _mount?.Dispose();
            _mount = null;
            _app = null;
        }
    }
}

Скачать AppBootstrap.cs

Добавьте App Bootstrap на тот же App с UI Document. Нажмите Play. Теперь видны светлый фон, заголовок и фиолетовая кнопка; счётчик по-прежнему работает. Выключите и включите App: появится только один экран, а число вернётся к нулю, поскольку этот Bootstrap создаёт новые зависимости на каждую активацию.

7. Убедитесь, что вы понимаете, куда вносить изменения

  1. В CounterPage замените gap с 16f на 24f. Расстояние между элементами увеличится.
  2. В AppTheme измените Accent. Изменится основной цвет кнопки без правки CounterPage.
  3. В AppDependencies замените ProjectCount.Value++ на ProjectCount.Value += 2. Кнопка начнёт добавлять по два.
  4. Добавьте Reset() в AppDependencies и вторую кнопку в CounterPage. Не вызывайте Mount заново и не создавайте новый State внутри Build.

Во время обучения сохраняйте C# вне Play Mode, ждите компиляции и запускайте Play снова. Rebuild не компилирует C# и не является hot reload. Вывод в Game без Play через генерацию UXML — отдельный editor-preview workflow: экспорт визуального состояния не заменяет работающие callbacks приложения. Подробнее о Rebuild, Restart и компиляции.

Если что-то не получилось

Пустое окно Game
Сначала проверьте Console. У App должны быть включены UI Document и один Bootstrap/FirstScreen, назначены Panel Settings, а Target Texture — пустой. Runtime-код этого урока работает только в Play Mode. Bootstrap ждёт live panel: выключенный UI Document её не создаёт.
Нельзя добавить скрипт как компонент
Имя файла должно совпадать с именем MonoBehaviour; исправьте все ошибки компиляции. AppRoot, AppTheme, AppDependencies и CounterPage не являются компонентами сцены.
Button — ambiguous reference
Используйте alias UIDocument как в полных файлах. Либо пишите LumaFlow.Button явно. Не удаляйте случайные using в надежде исправить все ошибки.
Счётчик не обновляется или всегда равен нулю
Число должно читаться через ReactiveBuilder, а State — создаваться вне Build. Проверьте, что кнопка меняет тот же экземпляр State, который получает builder.
Два одинаковых интерфейса
Удалите First Screen при переходе к App Bootstrap; не монтируйте приложение одновременно из двух компонентов.
После выключения App данные исчезли
В структурированном примере это ожидаемо: OnEnable создаёт новые зависимости. Для сохранения между сценами нужен отдельный владелец данных, для сохранения между запусками — запись на диск. MountHandle не является системой сохранения.
Хочу начать без пяти файлов
Останьтесь на FirstScreen. Выделяйте тему, страницы и зависимости, когда они действительно нужны. Урок показывает обязанности, а не обязательный шаблон для любого окна.

Куда идти дальше

Для начала достаточно запомнить: Bootstrap запускает, Dependencies предоставляет данные, Root собирает, Theme оформляет, Page описывает экран.

Widget, Element, State и Key → правила компоновки → контролы и формы → навигация и оверлеи. Справочник API полезен, когда уже понимаете, какую задачу решаете.
