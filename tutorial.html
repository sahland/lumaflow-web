What we will build — and how many files you actually need

Build a project counter: a heading, a number and an Add project button. A click updates the number without finding and changing native UI elements manually. Start with one file, then split the same app into five files and give it a shared theme.

AppBootstrap, AppDependencies, AppRoot and AppTheme are not required LumaFlow types.

These are names for classes you write in your application. You may rename them, combine them or leave them out. One MonoBehaviour is enough for your first screen. The structured example teaches responsibilities, not mandatory boilerplate.

You need Unity 6+, basic C# knowledge and Git for Git URL installation. These examples target LumaFlow 0.1.1; check your installed version in Package Manager. Every source file is complete, with no omitted services or hidden setup.

1. Install LumaFlow

  1. Open Window → Package Management → Package Manager (Window → Package Manager in some Unity versions).
  2. Choose + → Install package from git URL / Add package from git URL.
  3. Enter https://github.com/sahland/lumaflow.git and confirm.
  4. Wait for import and compilation. Verify that LumaFlow appears in Package Manager and Console has no red errors.

The UPM package name is com.sahland.lumaflow; its C# namespace is LumaFlow. Do not install a second copy if the package is already present. If Unity cannot find Git, install Git and restart the Editor. For a team project, pin a tested tag/commit in the Git URL rather than following a moving branch.

Checkpoint: the package compiles. No UI is visible yet; that is expected.

2. Give Unity somewhere to display the UI

  1. Create and save an empty scene. In Hierarchy, create an empty GameObject named App.
  2. Add a UI Document (UIDocument) component.
  3. In Project, choose Create → UI Toolkit → Panel Settings Asset and name it AppPanelSettings.
  4. Assign it to UI Document's Panel Settings field. For this lesson, use Scale Mode → Constant Pixel Size, Scale = 1. Leave Target Texture empty to render in Game rather than a RenderTexture.
  5. Check Theme Style Sheet in Panel Settings; assign Unity's default runtime theme if it was not assigned automatically. Keep default font settings for this test.
  6. Leave UI Document's Source Asset empty. This runtime example does not need UXML.

UIDocument connects the scene to UI Toolkit. Panel Settings controls output and scaling, not your LumaFlow application theme. rootVisualElement is the native container into which we mount the widget tree. A uGUI Canvas is not required.

Checkpoint: App has an enabled UI Document with Panel Settings assigned. Game may still be empty.

3. Get a working app in one file

Create Assets/FirstApp/FirstScreen.cs and paste the entire file below. Wait for compilation, add First Screen to App, enter Play Mode and open Game. The filename must match the MonoBehaviour class name.

FirstScreen.cs · complete file
#nullable enable
using System.Collections;
using LumaFlow;
using UnityEngine;
using UIDocument = UnityEngine.UIElements.UIDocument;
using Framework = LumaFlow.LumaFlow;

namespace LumaFlowDocs.Minimal {
    [RequireComponent(typeof(UIDocument))]
    [DisallowMultipleComponent]
    public sealed class FirstScreen : MonoBehaviour {
        private readonly State<int> _count = new(0);
        private MountHandle? _mount;
        private Coroutine? _startup;

        private void OnEnable() => _startup = StartCoroutine(MountWhenReady());

        private IEnumerator MountWhenReady() {
            yield return null;
            var document = GetComponent<UIDocument>();
            if (document.panelSettings == null) {
                Debug.LogError("Assign Panel Settings on the UIDocument.", this);
                _startup = null;
                yield break;
            }
            while (document.rootVisualElement?.panel == null) yield return null;
            _mount = Framework.Mount(BuildScreen(), document.rootVisualElement);
            _startup = null;
        }

        private Widget BuildScreen() => new Scaffold(new Center(new Padding(
            new Column(new Widget[] {
                new Text("My first LumaFlow app"),
                new ReactiveBuilder<int>(_count,
                    value => new Text($"Projects: {value}")),
                new Button("Add project", () => _count.Value++)
            }, gap: 12f), EdgeInsets.All(24f))));

        private void OnDisable() {
            if (_startup != null) StopCoroutine(_startup);
            _startup = null;
            _mount?.Dispose();
            _mount = null;
        }
    }
}

Download FirstScreen.cs

Expected result: a heading, Projects: 0 and Add project. Click three times: the label becomes Projects: 3. Styling is intentionally basic; a custom theme comes later.

MountWhenReady is a startup coroutine. yield return null gives Unity one frame; the loop then waits for UIDocument to attach to a live panel. This prevents mounting too early on devices. It finishes after mounting: there is no permanent Update loop. Enable UI Document together with App.

Framework is an alias for the class LumaFlow.LumaFlow. The UIDocument alias imports only that Unity type. Importing both namespaces with using UnityEngine.UIElements; and using LumaFlow; would make Button ambiguous.

4. Follow one click before learning every framework term

  1. new Button(..., () => _count.Value++) supplies an action to run on a press. () => means “run this function later”, not during Build.
  2. State<int> stores an integer and notifies subscribers when it changes; it is more than a local variable.
  3. ReactiveBuilder<int> receives that State and a function that describes its current label. A change schedules an update to that branch.
  4. Column arranges children vertically, gap separates them, Padding adds inner space, Center centers the content and Scaffold provides the main screen region.

A Widget is a description of the desired UI, not a GameObject. Build creates descriptions; LumaFlow reconciles them with its mounted tree and UI Toolkit renders them. Do not call Mount on every click or perform network requests/audio playback inside Build.

Create state once, in an owner.

_count is a component field, not a local variable in BuildScreen. Rebuilding does not reset it. State<T> has no Dispose method; ReactiveBuilder's subscriptions are removed when its branch unmounts. If you call Subscribe manually, dispose the returned subscription yourself.

MountHandle controls an existing mounted tree. Dispose removes its UI and subscriptions. OnEnable starts the app; OnDisable cancels startup and disposes the mount. This is not disk persistence: restarting Play Mode may reset the number.

A small C# glossary: namespace groups classes and avoids name conflicts; readonly prevents replacing a field reference after initialization; static means data belongs to the class rather than each screen. #nullable enable enables null checks: ? allows null, ?. calls a member only when the object exists, and ! tells the compiler the object is known to exist at this point. The ! operator is not a runtime check.

5. When the app grows: give each class one job

The single-file app already works. Splitting it helps people keep startup, data, styling and layout separate. Only AppBootstrap is a scene component. Do not try to attach all five classes to GameObjects.

Application classes, not package requirements
ClassPlain-language jobOwner / what to change here
AppBootstrapThe scene's power switch: wait for the panel, compose the app, Mount, then Dispose.Unity invokes OnEnable/OnDisable. Change startup and lifetime here, not button layout.
AppDependenciesShared objects the screen needs. Here, just the counter and its add action.Bootstrap creates it once per activation. Saving/network services can be added later; none are required now.
AppRootThe top Widget that combines the theme and initial page.Bootstrap creates and mounts it. Change shared wrappers and the starting page here.
AppThemeShared colors, text styles and control defaults.Static data created once. Change visual defaults here, not business logic.
CounterPageOne screen's layout and the connection between its button and action.AppRoot creates it. Add text, spacing, buttons and reactive branches here.
Unity → AppBootstrap → AppDependencies
                    → Mount(AppRoot, UIDocument.rootVisualElement)
                              → Theme → Scaffold → CounterPage

AppRoot is a Widget, not UIDocument.rootVisualElement. AppTheme is LumaFlow configuration, not Panel Settings or Unity's Theme Style Sheet. AppDependencies is a plain C# object, not a required dependency-injection container. Names such as Controller, Presenter and AppShell are also architectural choices, not magic framework requirements.

6. Split the same example into files

Exit Play Mode. Remove First Screen from App before adding the new bootstrap: otherwise two components will mount two apps into one document. You may keep its source file. Create Assets/FirstApp/Structured, add all five files below and wait for compilation. Their shared namespace LumaFlowDocs.Structured avoids conflicts with existing AppRoot/AppTheme classes.

Assets/FirstApp/Structured/
  AppBootstrap.cs     ← the only MonoBehaviour
  AppDependencies.cs  ← data and actions
  AppRoot.cs          ← root composition
  AppTheme.cs         ← styling
  CounterPage.cs      ← screen layout

AppDependencies.cs — give data an owner

The counter lives outside Build. AddProject changes it. Constructor injection gives the page the same counter instead of creating another one. For a tiny app you could pass State directly; the extra class illustrates a path for growth.

AppDependencies.cs · complete file
using LumaFlow;

namespace LumaFlowDocs.Structured {
    public sealed class AppDependencies {
        public State<int> ProjectCount { get; } = new(0);

        public void AddProject() => ProjectCount.Value++;
    }
}

AppTheme.cs — one source of visual defaults

ThemeData combines colors, typography, spacing, radii and button styles. OnPrimary means text on the primary action; Canvas is Scaffold's background. Creating a theme does not display it: AppRoot applies it using Theme. An explicit widget style may override theme values.

AppTheme.cs · complete file
using LumaFlow;
using UnityEngine;

namespace LumaFlowDocs.Structured {
    public static class AppTheme {
        private static readonly Color Ink = new Color32(44, 48, 62, 255);
        private static readonly Color Paper = new Color32(245, 244, 240, 255);
        private static readonly Color Accent = new Color32(98, 83, 150, 255);

        public static ThemeData Data { get; } = new(
            colors: new ColorScheme(
                canvas: Paper, surface: Color.white, surfaceVariant: Paper,
                primary: Accent, primaryContainer: Paper, onPrimary: Color.white,
                onSurface: Ink, onSurfaceVariant: Color.gray, outline: Color.gray),
            typography: new TypographyTheme(
                title: new TextStyle(Ink, 26f, FontStyle.Bold),
                headline: new TextStyle(Ink, 20f, FontStyle.Bold),
                body: new TextStyle(Ink, 16f),
                label: new TextStyle(Color.white, 16f)),
            spacing: new SpacingTheme(4f, 8f, 12f, 20f, 32f),
            radius: new RadiusTheme(
                BorderRadius.All(8f), BorderRadius.All(12f), BorderRadius.All(20f)),
            buttonTheme: new ButtonTheme(
                primary: new ButtonStyle(background: Accent, foreground: Color.white,
                    padding: EdgeInsets.Symmetric(horizontal: 20f, vertical: 12f),
                    shape: BorderRadius.All(12f), minimumSize: new Vector2(120f, 48f)),
                secondary: new ButtonStyle(background: Paper, foreground: Ink,
                    padding: EdgeInsets.All(12f), shape: BorderRadius.All(12f))));
    }
}

CounterPage.cs — describe the screen

StatelessWidget means the Widget itself does not own mutable local UI state, not that the screen cannot change. ReactiveBuilder watches the supplied State. BuildContext provides the current branch's settings; Theme! is valid here because AppRoot always wraps this page in Theme.

CounterPage.cs · complete file
using LumaFlow;

namespace LumaFlowDocs.Structured {
    public sealed class CounterPage : StatelessWidget {
        private readonly AppDependencies _app;

        public CounterPage(AppDependencies app) => _app = app;

        public override Widget Build(BuildContext context) => new Center(new Padding(
            new Column(new Widget[] {
                new Text("Project counter", context.Theme!.Typography.Title),
                new ReactiveBuilder<int>(_app.ProjectCount,
                    value => new Text($"Projects: {value}")),
                new Button("Add project", _app.AddProject)
            }, gap: 16f), EdgeInsets.All(24f)));
    }
}

Download CounterPage.cs

AppRoot.cs — combine the theme and page

Theme supplies settings to descendants, Scaffold provides the screen region and CounterPage describes its contents. Navigation or OverlayHost can be added here later; the counter does not need them.

AppRoot.cs · complete file
using LumaFlow;

namespace LumaFlowDocs.Structured {
    public sealed class AppRoot : StatelessWidget {
        private readonly AppDependencies _app;

        public AppRoot(AppDependencies app) => _app = app;

        public override Widget Build(BuildContext context) => new Theme(
            AppTheme.Data,
            new Scaffold(new CounterPage(_app)));
    }
}

Download AppRoot.cs

AppBootstrap.cs — connect the app to the scene

Bootstrap owns the dependencies and MountHandle. It does not find native labels/buttons; the widget tree handles layout. Disabling first removes the UI, then releases the dependencies reference. This example contains only State, so AppDependencies needs no Dispose. If you add owned IDisposable services, dispose them after the mount.

AppBootstrap.cs · complete file
#nullable enable
using System.Collections;
using LumaFlow;
using UnityEngine;
using UIDocument = UnityEngine.UIElements.UIDocument;
using Framework = LumaFlow.LumaFlow;

namespace LumaFlowDocs.Structured {
    [RequireComponent(typeof(UIDocument))]
    [DisallowMultipleComponent]
    public sealed class AppBootstrap : MonoBehaviour {
        private AppDependencies? _app;
        private MountHandle? _mount;
        private Coroutine? _startup;

        private void OnEnable() {
            _app = new AppDependencies();
            _startup = StartCoroutine(MountWhenReady());
        }

        private IEnumerator MountWhenReady() {
            yield return null;
            var document = GetComponent<UIDocument>();
            if (document.panelSettings == null) {
                Debug.LogError("Assign Panel Settings on the UIDocument.", this);
                _startup = null;
                yield break;
            }
            while (document.rootVisualElement?.panel == null) yield return null;
            _mount = Framework.Mount(new AppRoot(_app!), document.rootVisualElement);
            _startup = null;
        }

        private void OnDisable() {
            if (_startup != null) StopCoroutine(_startup);
            _startup = null;
            _mount?.Dispose();
            _mount = null;
            _app = null;
        }
    }
}

Download AppBootstrap.cs

Add App Bootstrap to App alongside UI Document. Enter Play: a light background, heading and purple button appear, and the counter still works. Disable and enable App: only one screen should appear, with the count reset to zero because this Bootstrap creates new dependencies on each activation.

7. Check that you know where to make a change

  1. Change CounterPage's gap from 16f to 24f. The space between elements increases.
  2. Change AppTheme's Accent. The main button color changes without editing CounterPage.
  3. Replace ProjectCount.Value++ with ProjectCount.Value += 2 in AppDependencies. A click now adds two.
  4. Add Reset() to AppDependencies and a second button to CounterPage. Do not remount or create a new State in Build.

While learning, save C# outside Play Mode, wait for compilation, then enter Play again. Rebuild does not compile C# and is not hot reload. Viewing generated UXML in Game without Play is a separate editor-preview workflow: a visual snapshot does not replace the app's working callbacks. Read about Rebuild, Restart and compilation.

If something goes wrong

Game is empty
Check Console first. App needs an enabled UI Document and exactly one Bootstrap/FirstScreen, with Panel Settings assigned and Target Texture empty. This runtime lesson requires Play Mode. Bootstrap waits for a live panel; a disabled document cannot supply one.
The script cannot be attached as a component
The filename must match its MonoBehaviour class name. Fix all compilation errors. AppRoot, AppTheme, AppDependencies and CounterPage are not scene components.
Button is an ambiguous reference
Use the UIDocument alias shown in the complete files, or qualify LumaFlow.Button. Both UI namespaces contain a Button.
The counter does not update or stays at zero
Use ReactiveBuilder to read it and create State outside Build. The button must mutate the same State instance the builder receives.
Two identical screens appear
Remove First Screen when switching to App Bootstrap. Do not mount the application simultaneously from two components.
Disabling App loses its data
Expected in the structured example: OnEnable creates new dependencies. To retain data across scenes, give it a separate owner; to retain it across launches, save it to disk. MountHandle is not a persistence system.
I do not want five files yet
Keep FirstScreen. Extract themes, pages and dependencies when they become useful. The lesson explains responsibilities rather than prescribing boilerplate for every window.

Where to go next

Remember: Bootstrap starts, Dependencies supplies data, Root composes, Theme styles, Page describes the screen.

Widget, Element, State and Key → layout rules → controls and forms → navigation and overlays. Use the API reference once you know which task you are solving.
